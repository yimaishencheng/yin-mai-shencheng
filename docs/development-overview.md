# 隐脉申城 开发大纲

## 1. 项目目的

“隐脉申城”是一个面向 1930 年代上海地下党历史的可视化平台。项目通过上海图书馆开放数据，将历史人物、活动地点、重大事件、机构组织和人物关系组织成可检索、可浏览、可分析的数字历史资料库。

项目希望实现三类目标：

1. 展示：用地图、时间轴、人物画像、关系图谱呈现上海地下党历史网络。
2. 分析：通过异常标注、断裂节点、低活跃组织等维度提示史料空白。
3. 复用：建立可持续更新的数据抓取和合并流程，便于后续扩展史料来源。

## 2. 已有情况

### 2.1 技术栈

| 类别 | 技术 |
| --- | --- |
| 前端框架 | React 18 |
| 构建工具 | Vite 5 |
| 语言 | TypeScript |
| 样式 | Tailwind CSS 4 |
| 路由 | React Router 6 |

| 地图 | Leaflet + React Leaflet |
| 3D 大厅 | Three.js + React Three Fiber + Drei |

### 2.2 页面结构

| 路由 | 页面 | 主要能力 |
| --- | --- | --- |
| `/` | 三维档案大厅 | 3D 民国档案室、家具热点、光标跟随、点击进入各模块 |
| `/overview` | 数据摘要 | 年代曲线、重点人物速查、档案馆藏索引、数字底图 |
| `/map` | 时空地图 | 按年份和地点类型筛选活动网点 |
| `/graph` | 关系网络 | 人物关系图、人物简档、跳转人物画像 |
| `/timeline` | 历史时间轴 | 年份过滤、事件类型过滤、全文检索、分页 |
| `/portrait/search` | 人物检索 | 按姓名检索人物，支持只看信息完整人物 |
| `/portrait/:personId` | 人物画像 | 完整人物介绍、关联图谱、事件详案、活动轨迹 |
| `/anomalies` | 异常发现 | 消逝人物、高风险地点、网络断裂、低活跃组织 |

| 地点 | 6224 |

已有能力：

- 人物、地点、事件、机构、关系均已写入前端可读取的 JSON。
- 事件详情、建筑详情、武康路建筑事件、人物详情已抓取。
- 人物详情已覆盖全部 2848 个人物 URI。
- 空姓名人物已清除，地点不再出现“未知人员”。
- 日期清洗可修正 `924.12.9` 这类缺失前导 `1` 的年份。
- 人物档案带 `is_incomplete` 标记，前端可区分完整档案与“档案待考”。
- 原始数据保存在本地缓存目录，支持断点续跑。
- 已建立可重复执行的数据抓取和构建命令。

数据仍存在需要继续治理的部分：

- 当前完整人物约 861 人，信息待考约 1987 人。
- 部分事件详情机构名称仍缺少 URI，只能通过名称回查或保留为待解析标签。
- 地点坐标覆盖已提升，但仍有一部分地点只有名称没有精确坐标。
- 存在同名不同 URI 的人物，需要后续做去重与合并。

## 3. 网站界面美术与 UI 风格

### 3.1 整体风格

界面采用“民国档案 / 情报卷宗”暗色风格，目标是让历史资料看起来像被重新启封的秘密档案，而不是普通数据后台。

视觉关键词：

- 暗色宣纸与旧纸墨感
- 民国竖排、刻字、印章和火漆元素
- 电报卡片、档案夹、铆钉、装订线
- 数据面板像“卷宗柜”，不是营销型展示页
- 首页大厅使用 3D 线框档案室，保留线条感的同时使用网站统一的琥珀金/朱砂红/靛蓝配色
- 光标移动带有档案光晕、十字准星和 3D 光标光源跟随

### 3.2 色彩体系

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 背景 | `#08080f` | 深墨蓝黑，整体底色 |
| 面板 | `#0c0c14` / `#12121a` | 档案面板和卡片 |
| 主强调 | `#d4a853` | 旧纸黄 / 琥珀金 |
| 警示 | `#c44b4b` | 朱砂红 / 异常标记 |
| 辅助 | `#3d5a80` | 靛蓝，用于图表和次级信息 |
| 次级文本 | `#7a8a9e` | 烟青色，用于说明文字 |

### 3.3 字体与排版

- 中文标题使用衬线字体：`Noto Serif SC`、`Source Han Serif SC`、`SimSun`、`STSong`。
- 正文使用无衬线字体：`PingFang SC`、`Microsoft YaHei`。
- 标题普遍使用字距加宽和 `tracking-widest`，营造民国刊物排版感。
- 页面标题字号克制，卡片内标题保持紧凑，避免营销页式的大标题。

### 3.4 组件语言

- 侧边导航使用线装书装订边缘和节点装饰。
- 图表面板使用档案编号式标题，如 `[ 档号 1930-B ]`。
- 卡片使用电报折角、铆钉、火漆印章、断裂封条等装饰。
- 加载状态使用“启封档案”动画和“正在解密历史档案”文案。
- 地图和图表使用暗色主题，突出历史数据本身。
- 首页大厅中的家具热点点击后打开档案抽屉，再进入对应模块。

### 3.5 信息设计

- 页面采用多面板工作台布局，适合反复查看、筛选和跳转。
- 地图页右侧使用档案侧栏展示地点详情、关联人物和相关事件。
- 人物画像页拆分为左中右三栏：档案信息、局部关系网、活动轨迹。
- 时间轴采用左右交错卡片与红色节点，保持历史叙事感。

## 5. 后续开发路线

### 阶段一：数据治理

- 建立人物清洗规则，删除无任何有效信息且不在核心名单内的记录。
- 合并同一人物的多个 URI 或重复姓名。
- 继续解析事件详情中的机构名称和地点名称。
- 增加数据质量校验：重复 ID、空字段率、关系目标有效性。
- 对 `is_incomplete` 人物继续补充传记、职业、生卒和机构字段。

### 阶段二：功能补齐

- 新增机构名录页面，展示机构成员和关联事件。
- 修复异常页跳转地图后的高亮定位。
- 人物检索支持别名和曾用名。
- 时间轴和地图支持从事件详情直接跳转。
- 大厅增加更多家具、档案抽屉内容和页面转场动画。

### 阶段三：性能与工程化

- 使用 React Router 懒加载拆分页面。
- 将 ECharts 和 Leaflet 拆分为独立 chunk。
- 将 Three.js / React Three Fiber 拆分为大厅专用 chunk。
- 对大数据列表增加虚拟滚动或分页。
- 建立数据构建的自动化测试和 CI 检查。

## 6. 安全与隐私

本项目提交包不应包含 API Key、本地隐私路径或可识别参赛者的身份信息。

- API Key 仅通过环境变量或本地 `.env` 提供，不进入提交包。
- `.env`、`.env.oss`、缓存目录、构建目录和提交目录已加入忽略列表。
- 数据抓取脚本只读取公开开放数据接口。
- 提交前运行 `scripts/verify_submission.py` 和 `scripts/prepare_submission.ps1`，确认已清除 `.git`、真实凭据、本机路径和部署域名。
- 数据来源、授权限制和衍生字段说明见 `DATA_SOURCES.md`、`DATA_LICENSE.md` 与 `public/data/provenance.json`。
